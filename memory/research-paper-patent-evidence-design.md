**Design: 隧道病害可信复核专利算法路线**

Generated by office-hours on 2026-06-16  
Status: DRAFT  
Mode: Builder / Research + Patent

**Problem Statement**

当前项目已经能完成隧道病害 6 类语义分割、SegFormer B1 训练、增强模块评估和本地 Web 展示。下一阶段目标应更偏专利和算法，而不是把 Web 做成主角。Web 只作为验证与展示入口，真正要沉淀的是一套“分割结果可信复核算法链”。

核心问题是：隧道病害分割模型输出的 mask 可能因为 TTA 融合、小目标压缩、边界不确定、候选预测分歧和形态断裂而不可靠。系统需要一种算法方法，在没有 GT 的实时上传场景下仍能判断候选结果是否稳定、是否需要人工复核，并在有 GT 的实验集上证明这种复核信号与真实错误、融合损伤、小病害保护存在相关性。

**What Makes This Cool**

最值得老师记住的不是 Web，也不是“用了 SegFormer”，而是这条算法链：

> 多候选 mask 生成 -> 概率 TTA 对齐 -> fixed fusion -> 自适应 selected mask -> uncertainty/disagreement 估计 -> morphology_delta 形态变化分析 -> review priority / review queue 可信复核输出。

算法创新可以拆成 4 个更清晰的模块：

1. **多候选分割结果生成模块**  
   对同一隧道图像生成 `single mask`、`fused mask`、`hybrid mask` 等候选结果，保留融合前后的差异。

2. **融合损伤识别与自适应选择模块**  
   通过前景收缩、single/fused 一致性、protected pixels、候选 mask 稳定性，判断 fixed fusion 是否压掉小病害，并选择更可信的 `selected mask`。

3. **不确定性与分歧度复核模块**  
   使用 probability entropy、TTA disagreement、self-consistency 等信号，定位模型不确定区域和候选预测分歧区域。

4. **形态变化与复核排序模块**  
   用面积、连通域、骨架长度、主方向变化构造 `morphology_delta`，再综合 uncertainty、disagreement、融合损伤和形态变化生成 `review_priority` 与 `review_queue`。

一句话版本：

> 本项目提出一种面向隧道病害分割结果的可信复核方法，通过多候选掩膜一致性、不确定性、分歧度和形态变化分析，识别融合损伤并生成可解释的人工复核优先级。

**Premises**

1. 专利核心不放在分割主干模型，而放在“分割结果可信复核与证据生成”。SegFormer 是 backbone，不是主要创新点。

2. 技术效果重点不是 selected 一定超过 single mIoU，而是避免 fixed fusion 压掉小病害，并把不稳定预测排进人工复核队列。

3. 软著按完整软件系统申报，名称暂定为“隧道病害智能分割与可信复核分析系统 V1.0”。

4. 论文/展示服务于专利算法路线：实验和图表用于证明算法链条有效，而不是把 Web 系统本身作为核心创新。

**Approaches Considered**

**Approach A: 软著优先 + 专利交底同步**

Summary: 先整理系统说明、源代码清单、界面截图和现有证据，不大改实验。  
Effort: S  
Risk: Low  
Pros: 最快形成可提交成果；现有材料可直接复用；适合短期老师检查。  
Cons: 算法创新表达弱；更像系统实现，不像发明方法。  
Reuses: README、Web demo、软著草稿、patent notes、evidence pack、PPT。

**Approach B: 专利算法优先，可信复核方法强化**

Summary: 围绕多候选 mask、自适应选择、uncertainty、disagreement、morphology_delta 和 review queue 写成一套专利方法链，并用实验表和代表案例支撑技术效果。  
Effort: M  
Risk: Medium  
Pros: 最适合发明专利；创新点集中；不容易被问成“只是用了 SegFormer”；论文和软著都能反哺。  
Cons: 需要更严谨地抽象算法步骤、权利要求、附图和消融实验。  
Reuses: `enhancement_evidence.py`、`morphology_delta`、`review_queue_summary`、patent evidence pack、现有评估 JSON。

**Approach C: 论文优先，实验强化**

Summary: 把项目整理成研究论文路线，补 baseline 对比、消融实验、类别误差分析和可视化案例。  
Effort: L  
Risk: Medium-High  
Pros: 最像正式研究成果；能提高老师认可度；能补强专利证据。  
Cons: 工作量最大；容易把重点拉回论文系统展示；Web 和实验表可能喧宾夺主。  
Reuses: SegFormer 160000 iter 结果、adaptive evidence、Web demo、PPT/讲稿、patent notes。

**Recommended Approach**

选择 **Approach B: 专利算法优先，可信复核方法强化**，并吸收 C 的实验严谨性。

推荐原因：你明确说“更偏专利、更多算法、少一点 Web”。所以主线应从“工程系统展示”改成“可申请专利的方法链条”。论文不是放弃，而是作为证明算法有效的实验材料；Web 也不是放弃，而是作为可视化验证工具。

这条路线的核心产出应是：

1. **算法流程图**  
   输入图像 -> 候选 mask 生成 -> 概率融合 -> 融合损伤判断 -> 自适应 selected mask -> uncertainty/disagreement -> morphology_delta -> review priority。

2. **权利要求雏形**  
   - 一种隧道病害分割结果可信复核方法。
   - 一种隧道病害分割结果可信复核系统。
   - 一种计算机可读存储介质 / 计算机程序产品。

3. **算法模块定义**
   - 候选掩膜生成模块。
   - 融合损伤识别模块。
   - 自适应掩膜选择模块。
   - 不确定性与分歧度分析模块。
   - 形态变化分析模块。
   - 复核优先级排序模块。

4. **技术效果证据**
   - `selected vs fixed fused mIoU`
   - `protected pixels vs fused`
   - `successful guard events`
   - `error coverage`
   - `HU error precision`
   - `review queue high bucket` 中 fixed fusion harmed / selected recovered 的集中程度
   - 典型案例中的 morphology_delta 解释

5. **附图证据**
   - 方法流程图。
   - 模块结构图。
   - single/fused/selected mask 对比图。
   - uncertainty/disagreement 图。
   - morphology_delta 表或图。
   - review queue 排序示意图。

**Open Questions**

- 当前 adaptive selection 规则是否需要进一步形式化成可写入权利要求的步骤？
- `review_priority.score` 是否要固定成公式，还是保持为多因素加权规则？
- morphology_delta 是否只做解释，还是加入 selected mask 的选择决策？
- 是否需要补一个“无 GT 场景”的算法说明，强调实时上传时不能算 true mIoU，但可以算 self-consistency、uncertainty、disagreement 和 morphology_delta？
- 是否需要补 3 个消融：去掉 adaptive selection、去掉 uncertainty/disagreement、去掉 morphology_delta/review priority？

**Next Steps**

1. **先写专利交底书框架，而不是先写论文正文。**
   - 技术领域：隧道病害图像语义分割与可信复核。
   - 背景技术：现有分割方法只输出 mask，难以判断结果可靠性；固定 TTA 融合可能压缩小病害。
   - 发明内容：提出多候选 mask、自适应选择、不确定性、分歧度、形态变化和复核排序的一体化方法。
   - 有益效果：减少固定融合损伤、保护小病害、定位不可靠区域、输出人工复核优先级。
   - 实施例：使用 SegFormer B1 作为候选 mask provider，但方法不限定于 SegFormer。

2. **把算法链条公式化。**
   - 定义 `M_single`、`M_fused`、`M_selected`。
   - 定义前景收缩比例、protected pixels、self foreground IoU。
   - 定义 entropy uncertainty 和 TTA disagreement。
   - 定义 morphology_delta：面积变化、连通域变化、骨架长度变化、方向变化。
   - 定义 review priority score：风险、uncertainty、disagreement、一致性、融合收缩、形态变化的组合。

3. **补专利用消融实验清单。**
   - Single baseline。
   - Fixed fused baseline。
   - Selected without morphology_delta。
   - Selected with uncertainty/disagreement。
   - Full method with review queue。

4. **选 5 个专利实施例案例。**
   - Fixed fusion 压缩小病害，selected 恢复。
   - Uncertainty 高且覆盖真实错误区域。
   - Disagreement 明显，候选预测不稳定。
   - Morphology_delta 显示骨架缩短或连通域变化。
   - Limitation case：说明方法边界，避免过度主张。

5. **Web 降级为演示支撑。**
   - Web 不作为创新核心。
   - Web 只证明方法链条可运行、可展示、可生成报告。
   - PPT 中 Web 页面最多作为“实施系统界面”，不要让老师以为创新点是网页。

**What I Noticed**

你不是单纯想把项目做漂亮，而是想让它“能被认可”：能给老师看，能写软著，最好能往专利走。你现在的直觉是对的：如果继续强调 Web，很容易被看成展示系统；如果强调 SegFormer，又容易被认为只是用了现有模型。真正有差异化的是算法链条中间这部分：候选 mask 如何比较、融合损伤如何发现、形态变化如何解释、复核优先级如何生成。

所以修订后的方向应该更硬一点：少讲“系统多完整”，多讲“方法怎么判断结果可靠”。Web 只是外壳，专利要写的是里面这套可信复核算法。
